## Context

现状：程序为单文件 `Crosshair.cs`（441 行，csc 直接编译，无 .csproj），三个全局热键（`` ` ``/`F2` 切换显隐、`←`/`→` 切换地图）的虚拟键码硬编码在 `WH_KEYBOARD_LL` 钩子回调中，无配置存储。动机见 proposal.md - Why，行为要求见 specs/hotkey-settings/spec.md。

约束：
- 无第三方依赖（.NET Framework 4.0 自带能力），编译命令保持不变
- 项目惯例为单文件源码 + 便携 exe，数据以文本文件存放（Coordinate/*.txt 先例）
- 钩子为全局拦截（命中即消费按键，不传递给游戏），需在设置交互期间避免误触发

## Goals / Non-Goals

**Goals:**
- 零依赖实现快捷键配置的读写、持久化、冲突检测
- 设置窗口交互简单直观：点击「修改」→ 按新键 → 保存
- 配置与代码解耦：钩子分发从硬编码改为查配置
- 默认行为与现状完全一致（未配置时 `` ` ``/`F2`、`←`、`→` 均可用）

**Non-Goals:**
- 组合键（Ctrl/Alt/Shift + 键）支持 —— 当前默认键全为单键，spec 未要求
- 绑定按键的危险性校验（如拦截游戏常用键）—— 由用户自行权衡，文档提示
- 其他设置项（地图池等已在托盘菜单中，不在设置窗口内）
- 多配置文件或注册表方案

## Decisions

### D1: 每个动作支持绑定多个键，设置窗口以「整体替换」方式修改

内部模型中每个动作可绑定 0..N 个键，配置行以逗号分隔存储（`Toggle=F2,Oemtilde`）。设置窗口点击某动作的「修改」进入监听，按下一次键即整体替换该动作的绑定为单键。

- **理由**：现状「切换显隐」同时绑 `` ` `` 与 `F2` 两个键，单键模型要么丢功能要么需要特例逻辑；多键模型自然表达默认态，且「整体替换」交互让用户心智模型简单（改一次 = 替换）。
- **替代方案**：每个动作单键 + F2 硬编码辅助键（自定义后 F2 神秘失效，行为怪异）；多键增删式交互（窗口复杂，非本次所需）。

### D2: 配置持久化为 exe 同目录 `hotkeys.ini` 文本文件

格式：每行 `动作名=键名1,键名2`，键名用 .NET `Keys` 枚举名（`Oemtilde`/`Left`/`Right`/`F2`/字母数字大写），`KeysConverter` 双向转换；显示名对少数特殊键做友好修正（如 `Oemtilde` → `` ` ``）。启动时加载，文件缺失或解析失败（未知动作名/非法键名）时该项回退默认值。

- **理由**：便携（跟随 exe）、零依赖、人类可读可手改；符合项目文本文件先例。
- **替代方案**：注册表（写入用户系统、不便于迁移）；XML（对 3 行配置过重）；手写 JSON 解析（无内置 JSON，引入解析代码不值得）。

### D3: 设置窗口为模态，交互期间钩子暂停消费

设置窗口用 `ShowDialog()` 模态打开；新增 `settingsOpen` 标志，`HookCallback` 检测到该标志时对全部按键直接 `CallNextHookEx`（不消费、不触发任何动作），避免用户在监听「按新键」时意外触发切换/翻页。

- **理由**：低层钩子独立于消息泵，窗口打开时钩子仍在工作；若不禁用，用户按下本想绑定的 `` ` `` 会先触发显隐切换。
- **替代方案**：Unhook 再重装（复杂且有窗口期）；不改（交互事故）。

### D4: 冲突检测在保存时执行，失败则整体拒绝

「确定」按钮触发校验：将各动作当前待保存的键集合全局查重，同一键出现在两个不同动作 → `MessageBox` 提示冲突动作与按键，不写入配置、不关窗，各动作保持保存前绑定；同一动作内重复键自动去重。

- **理由**：spec 场景要求「保存时提示冲突并拒绝，绑定保持不变」；捕获阶段即校验会打断按键流且无法覆盖「跨窗口改多个动作后才发现冲突」的情况。
- **替代方案**：捕获时实时校验（交互碎，spec 场景不符）。

### D5: 钩子分发改为构建动作→按键集映射

启动加载配置后与设置保存后，重建 `Dictionary<int vk, Action>`（或等价映射）。`HookCallback` 仅查映射分发，不再引用任何硬编码 VK 常量。

- **理由**：单点重建保证配置修改后立即生效（无需重启），删掉硬编码 VK 常量避免双真相。
- **替代方案**：每次按键遍历配置（低频事件下亦可行，但重建映射更直接且为后续扩展留位）。

## Risks / Trade-offs

- **全局拦截用户游戏按键**（如用户把显隐设为 `Q`，游戏内按 Q 会被消费）→ 与现状一致（当前默认键同样拦截），在 README「注意事项」与设置窗口内以提示文字说明，由用户自行权衡。
- **配置文件损坏导致行为异常** → 解析失败逐项回退默认值，不阻止程序启动；文件可随时删除重建。
- **Escape 键语义**：监听「按新键」时按下 Escape 视为取消本次修改而非绑定 → 明确写入设置窗口提示；如需绑定 Escape 为热键属于边界情况，本次不支持。
- **设置窗口与游戏同屏**：模态窗口会短暂抢焦点 → 属于可接受的设置期行为，保存/取消后焦点返回游戏。

## Migration Plan

- 无既有配置需迁移：首次运行时配置文件不存在，全部使用默认键，随后执行任何保存操作才落盘生成 `hotkeys.ini`（非首次启动即生成文件，避免无谓写盘）。
- 回滚：删除 exe 同目录 `hotkeys.ini` 即恢复出厂快捷键，无需重编译。
