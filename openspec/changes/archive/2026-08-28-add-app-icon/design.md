## Context

现状：托盘图标（`SetupTrayIcon`）用 Bitmap 直接绘制 16×16 红点 `(255,60,60)`（`FillEllipse(3,3,10,10)`）转 HICON；主窗口无图标设置，exe 无图标资源（csc 无 `/win32icon`）。动机见 proposal.md - Why，行为要求见 specs/app-icon/spec.md。

约束：
- 单文件源码 + csc 直接编译，`.ico` 需作为编译期资源（`/win32icon`）
- 图标绘制逻辑应单一来源，避免托盘与窗口图标样式分叉

## Goals / Non-Goals

**Goals:**
- exe 文件图标与窗口图标统一为红点样式（与托盘一致）
- 图标生成逻辑单点复用；编译命令可重复执行且结果稳定

**Non-Goals:**
- 多尺寸/高 DPI 图标集（32×32 单尺寸，窗口与资源管理器自动缩放即可）
- 图标主题化/深色适配
- 修改托盘图标现有外观

## Decisions

### D1: 红点 `.ico` 作为编译资源，单尺寸 32×32

新增 `pubg.ico`（32×32，透明背景 + 中央红色圆点），编译命令加入 `--% /win32icon:pubg.ico`。

- **理由**：`/win32icon` 是 csc 注入 exe 图标的唯一标准方式；32×32 在资源管理器任意缩放比例下视觉清晰；文件随仓库提交，构建可复现。
- **替代方案**：运行时生成并 `ExtractIcon`（无法改变 exe 文件静态图标）；多尺寸 ICO（收益低，生成复杂度高）。

### D2: 图标生成逻辑收敛为单一函数

新增 `DotIcon.Create(int size)`（或等价静态方法）：任意尺寸 Bitmap 上按比例绘制红点，供托盘（16）与窗口（32）共用；`pubg.ico` 用同一逻辑生成一次后入库，代码运行时再经 `this.Icon = DotIcon.Create(32)` 设置窗口图标。

- **理由**：单一来源保证托盘/窗口/exe 三处图标几何与颜色一致；测试可对生成结果断言。
- **替代方案**：手工制作 .ico（不可复现、与代码绘制逻辑无关联）。

## Risks / Trade-offs

- **ico 与代码漂移**：`pubg.ico` 由代码逻辑生成，若配色调整需重新生成 → 在任务中固化生成流程（脚本/单测），HANDOFF 注明生成方法。
- **单尺寸缩放模糊**：32×32 在小尺寸（16）缩放时红点边缘可能略糊 → 透明背景+纯色圆点，缩放观感可接受；与现有 16×16 托盘图标并存。

## Migration Plan

- 现有运行实例无需迁移；重新编译即获得新 exe 图标，窗口图标随新 exe 生效。
- 回滚：删除 `pubg.ico` 并移除编译命令中的 `/win32icon`，重编译即复原。
